# 共通指示

## 記述言語

このグローバル指示は日本語で記載する。各プロジェクトの `AGENTS.md` は英語を基本とする。

## 質問への回答

質問を受けたときは、可否と実現方法を回答する。実装、ファイル変更、コマンド実行は、明示的な依頼を受けて開始する。

## 表現

一般的なカタカナ語として定着していない英語の技術用語は、日本語の表現に置き換える。文脈に応じて意味を明確にし、たとえば `gate` は「検査条件」または「承認段階」と表現する。

## ドキュメント

### 目的と適用範囲

以下は、報告書、提案書、仕様書、意思決定記録など、単独で読まれるドキュメントを作成・改訂するときの必須基準とする。読者が作成時の会話、暗黙の前提、公開されていない思考過程を知らなくても、内容を理解し、検証し、利用できるようにする。

文章の見栄えや短さよりも、必要な情報の充足、事実の正確さ、根拠と結論のつながり、判断への有用性を優先する。成果物の説明書は、目的、構成、利用方法、保守に必要な事項で構成する。その他の文書は、用途と読者が必要とする情報に合わせて構成する。

作成時の会話の経緯、判断の変遷、釈明は、単独で読む読者の理解や利用に必要な情報ではないため、記載対象から除く。意思決定の根拠や比較した選択肢は、読者が判断を検証するために必要な情報として記載する。

### 1. 会話を知らない読者にも理解できる内容

- 想定読者と文書の目的を明確にする。
- 主題の理解に必要な背景を説明する。
- 想定読者が知っているとは限らない専門用語を定義する。
- 関連するシステム、組織、手順、制約は、それを前提とする説明より先に紹介する。
- 問題、その影響、対応が必要な理由を示す。
- 証拠、結論、推奨事項を結ぶ理由を説明する。
- 必要な文脈は本文に含めるか、参照先を明示した閲覧可能な資料で補う。

「先ほど議論したとおり」「前述の問題」「提案した方法」などの表現は、参照対象が文書内で明確な場合に用いる。説明の範囲は想定読者に合わせ、一般常識の説明で分量を増やさない。

### 2. 根拠と情報の確かさ

検証済みの事実、他者から報告された主張、仮定、推定、解釈、推奨事項、不明点を区別する。

重要な主張には、次の情報を添える。

- 裏づけとなる証拠、または確認可能な出典。
- 証拠が結論を支持する理由。つながりが自明でない場合は説明する。
- 関連する不確実性と限界。
- 数量を示す場合の単位、日付、比較の基準、比較条件。

データ、引用、関係者の意見、要件、意思決定の理由を捏造しない。必須の情報が得られない場合は、欠けている情報を明示する。一般論やもっともらしい断定で根拠の不足を埋めない。

### 3. 因果関係と意思決定の説明

読者が推論をたどれる形で説明する。重要な推奨事項では、文書の目的に応じて次の内容を示す。

1. 現状と具体的な問題。
2. 目的と適用される制約。
3. 検討した選択肢。
4. 評価基準。
5. 各選択肢の根拠と、得られる利点に伴う不利益。
6. 推奨する選択肢を選ぶ理由。
7. 予想される結果、リスク、未解決事項。
8. 必要な決定または行動。

文書に関係する項目を選び、不要な節を機械的に追加しない。結論では目的を言い換えるだけで終えず、実現の仕組みを説明する。たとえば「業務効率が向上する」と述べる場合は、対象の業務と、効率が向上する仕組みを具体化する。

### 4. 根拠のない対比と釈明的な否定の除去

文脈に存在しない解釈や反論を持ち出して否定し、文章を強調する構成を避ける。次のような表現は、意図する事実や結論を直接述べる形に改める。

- 「単なるXではなく、Yである」
- 「目的はXではなく、Yである」
- 「これはXを意味するものではない」
- 「重要なのは……」
- 「Xと理解すべきではない」
- 「単にXするのではなく、Yを目指す」

対比や否定は、実際に示された解釈や具体的に予想される誤解を訂正する必要があり、その区別が読者の理解や判断を変える場合、または実際の制約・除外・要件を伝える場合に用いる。「しないこと」や実装しない理由を説明する場合は、一般的な慣行から外れる判断、または機能の実装対象からの意図的な除外を、その理由とともに示す。コードコメントにも同じ基準を適用する。

たとえば「単なる費用削減ではなく、戦略的な変革である」ではなく、「請求書処理を自動化して手作業の照合を減らし、担当者の作業時間を例外対応に振り向ける」と記述する。説得力を演出するために対立意見や誤解を作り出さない。

### 5. 情報を伴わない強調と抽象表現の除去

「包括的で堅牢な解決策」「シームレスな連携」「新たな可能性を開く」「価値を創出する」「急速に変化する現代」「成功への重要な一歩」「全体最適化」「変革的な効果」などは、具体的な意味と根拠を示せる場合に用いる。

- 漠然とした利点よりも、観察できる動作や振る舞いを示す。
- 大きな目標を掲げるだけでなく、具体的な仕組みを説明する。
- 宣伝的な表現よりも、定義された成果を示す。
- 一般的な注意書きよりも、具体的な制約を示す。
- 形容詞で強調するよりも、関連する証拠を示す。

各段落には、必要な文脈、新しい事実、説明、証拠、分析、判断や推奨事項、意味のある限界や条件のいずれかを含める。いずれも含まない段落は削除する。

### 6. 必要な情報を保った簡潔さ

- 重複や冗長な前置きを削る。
- 理解に必要な説明を残す。
- 圧縮すると仮定や因果関係が隠れる場合は、推論を詳しく説明する。
- 比較を確認しやすくする場合は表を使う。
- 関係性、因果関係、条件の説明には文章を使う。
- 内容のある説明を、意味の説明がない単語の羅列に置き換えない。

短さのために判断に不可欠な情報を省かず、詳しく見せるためだけの加筆も避ける。

### 7. 読者の疑問に沿った構成

判断を支援する文書は、読者が必要とする次のような問いへの答えを中心に構成する。

- 何が起きているか。
- なぜ重要か。
- 評価を裏づける証拠は何か。
- どのような選択肢があるか。
- 各選択肢にはどのような利点と不利益があるか。
- 何を推奨し、その理由は何か。
- 次に何を決め、何を実行する必要があるか。

解説文書では、理解の前提となる概念、仕組み、例、その意味や影響を優先する。「背景・課題・解決策・効果・結論」などの定型構成は、実際の情報に適している場合に用いる。見出しは配下の内容を正確に表すものにする。

### 8. 執筆と検証の分離

執筆前に、次の準備を行う。

1. 想定読者、目的、文書の利用方法を明確にする。
2. 利用可能な事実、証拠、仮定、不足する情報を整理する。
3. 読者の理解や行動に必要な情報を特定する。
4. その情報に沿って構成を設計する。

執筆後は、完成した文書そのものを主な資料として、執筆とは別の見直しを行う。

- 元の会話を知らない想定読者が理解できるか。
- 必須の概念を、それを使う説明より先に紹介しているか。
- 主要な結論に至る推論を読者がたどれるか。
- 重要な主張に裏づけがあるか。
- 比較に明示的な基準があるか。
- 重要な不確実性が隠れていないか。
- 根拠のない否定、作り出した対比、釈明的な注意書きがないか。
- 無関係な別のプロジェクトにも当てはまる一般論にとどまっていないか。
- 想定する判断や行動に必要な情報がそろっているか。

文章が自然に読めることだけを、必要な情報がそろっている証拠としない。

### 9. 改訂の手順

欠陥を見つけたら、修正前に種類を特定する。

- 文脈の不足。
- 証拠の不足。
- 裏づけのない推論。
- 用語の曖昧さ。
- 比較の不備。
- 判断基準の欠落。
- 根拠のない否定。
- 内容を伴わない抽象表現。
- 冗長さ。
- 構成の不整合。

表現を言い換えるだけで済ませず、情報や論理の欠陥そのものを修正する。修正に必要な情報を得られない場合は、不確実性を保ったまま、必要な情報を明示する。

### 10. 完成の判定基準

次の条件を満たした文書を完成とする。

- 目的と想定読者が明確である。
- 単独で読むために必要な文脈が含まれている。
- 中心的な主張に裏づけがあるか、確かさに応じた条件や留保が示されている。
- 提示した情報から結論を導ける。
- 判断に関係する代替案、制約、リスクが、必要に応じて扱われている。
- 捏造された証拠や根拠のない確信が含まれていない。
- 不要な釈明的否定や作り出した対比が含まれていない。
- 汎用的な宣伝文句や説明のない抽象表現が含まれていない。
- 作成時の会話を参照せずに理解できる。

必須の条件を満たせない場合は、その限界を明示し、完成扱いにしない。読者が情報を理解し、検証し、行動に移せることを、文章の見栄えより優先する。

## Nix

Nix 式を作成または更新するときは、入力を最小化し、バイナリキャッシュを最大限に利用できる構成にする。変更範囲に応じて派生物を分割し、局所的な変更が依存コンポーネント全体の再構築を誘発しないようにする。特に、アプリケーションバンドルの作成は依存コンポーネントの構築と分離する。

## コマンドラインツール

必要なコマンドラインツールが恒久的な構成に含まれない場合は、Nix の一時シェルを用意して利用する。

## 開発サーバーへの接続
macOSホストからLinuxに接続して実機検証を行う場合はssh nixosで接続する。Windowsに接続する場合はssh surfaceで接続する。
